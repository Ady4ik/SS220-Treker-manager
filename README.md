# SS220 Treker Manager

Discord-бот для переноса всего Discord Forum в GitHub Issues и GitHub Projects v2 по команде `/migrate`.
Форум: `https://discord.com/channels/1097181193939730453/1385519706781253632`.

## Возможности

- `/migrate` без аргумента читает все доступные посты форума, включая архивные.
- `/migrate source:<ссылка на форум>` читает весь указанный форум.
- `/migrate source:<ссылка на пост>` читает весь пост и все его ответы.
- Для каждого поста создаётся один Issue; ответы сохраняются в Issue полной хронологической историей.
- Ссылка на отдельное сообщение внутри поста тоже читает **весь пост**. Ссылка на сообщение обычного текстового канала и текстовый ввод остаются одиночными источниками.
- `баг/bug` → label `bug`; `фича/feature` → `enhancement`. Неизвестный или конфликтующий тип возвращает ошибку.
- Summary — краткая выдержка до 600 символов. Основной текст сохраняется и разбивается по известным полям: описание, шаги, ожидаемый/фактический результат, окружение. Это локальный разбор без LLM.
- Отдельный маршрут каждого типа задаёт репозиторий, дополнительные labels, Project и Status. Недостающие labels создаются.
- В Issue сохраняются ссылка на Discord и ссылки на вложения. Файлы не скачиваются; ссылки Discord могут истечь.
- Длительный обход работает фоном и имеет `/migration-status`; отчёт хранится в `data/jobs`.
- SQLite и маркер источника в Issue позволяют повторить команду после сбоя Project без нового Issue.
- `DRY_RUN=true` показывает результат разбора без запросов к GitHub.

## Настройка

Требуется Python 3.11+. В PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
Copy-Item routes.example.json routes.json
```

1. В Discord Developer Portal создайте application и bot. Включите **Message Content Intent**. Пригласите бота со scopes `bot` и `applications.commands`, правами View Channels, Read Message History, Send Messages и Send Messages in Threads. Для приватных тредов бот должен быть участником.
2. Укажите `DISCORD_TOKEN` в `.env`. `DISCORD_GUILD_ID` ускоряет регистрацию команды на тестовом сервере; без него команда глобальная и может появиться с задержкой.
3. Укажите `GITHUB_TOKEN`: например, classic PAT с `repo` и `project`, доступом к целевому репозиторию и Project. При использовании fine-grained PAT нужны Issues read/write и соответствующее разрешение Projects read/write у владельца; проверьте доступ к обоим ресурсам и SSO организации.
4. В `routes.json` замените примеры на реальные репозитории и борды. `project_number` — номер из URL `/users/OWNER/projects/N` или `/orgs/OWNER/projects/N`; `project_owner_type` — `user` или `organization`. `status_field` и `status` должны точно совпадать с названиями в Project. Удалите `status`, если нужно лишь добавление на борду.
5. Добавьте `DISCORD_FORUM_CHANNEL_ID=1385519706781253632` в `.env` для вашего форума. Запустите `.venv\Scripts\python -m bot` и проверьте `/migrate` в режиме dry-run. Затем установите `DRY_RUN=false` и перезапустите.

Репозиторий кода бота и репозиторий назначения Issue могут быть разными. Дополнительный аргумент `repository` должен совпадать с маршрутом данного типа. Другие теги не переносятся произвольно: нужные labels укажите в маршруте.

## Пример трекера

```text
Тип: баг
Заголовок: Не открывается шлюз
Описание: После подачи питания шлюз не реагирует на нажатие.
Шаги: Подать питание, нажать на шлюз.
Ожидаемый результат: Шлюз открывается.
Фактический результат: Нет реакции.
Окружение: Карта и номер раунда.
```

## Доступ и повторные команды

Команда доступна участникам с Manage Messages; право проверяется для каждого поста. Форум должен находиться на том же сервере и быть доступен вызывающему участнику и боту. Читаются активные и архивные посты через Discord API, а история каждого поста запрашивается с `limit=None`, поэтому ограничение в 100 сообщений не применяется.

Запускайте **один экземпляр** бота и сохраняйте каталог `data/`. Один форумный обход выполняется как фоновое задание; параллельный обход того же сервера блокируется. При повторе используется тот же Issue: **для постов тело Issue заменяется актуальной историей**, включая новые ответы. Ручные изменения тела будут перезаписаны; заголовок, labels и состояние Issue сохраняются. Добавление в Project повторяется, Status устанавливается заново. Ключ поста совпадает с ключом его первого сообщения в предыдущей версии.

### Запуск для этого форума

```text
/migrate source:https://discord.com/channels/1097181193939730453/1385519706781253632
/migration-status job_id:<ID из ответа>
/migration-status job_id:<ID из ответа> report_file:true
```

Без `source` используется `DISCORD_FORUM_CHANNEL_ID`; если он не задан, команда внутри поста форума выбирает **весь родительский форум**. Для одного поста передайте его ссылку явно.

Задание читает сообщения, созданные до его запуска. Это не непрерывный мониторинг и не транзакционный снимок: удалённые сообщения недоступны, редактирование/перемещение постов во время обхода может менять результат. Ответы не переопределяют тип и заголовок трекера. Summary содержит выдержку исходного сообщения и первых ответов, полная история — всех доступных сообщений, включая текст embeds и ссылки на вложения.

Прогресс и ошибки каждого поста сохраняются в `data/jobs/<ID>.json` (путь меняется через `JOBS_DIRECTORY`). Отчёт содержит краткие выдержки сообщений, поэтому защитите доступ к этому каталогу. В Discord отчёт доступен только инициатору на исходном сервере; он не публикуется в общий канал. После перезапуска незавершённое задание помечается `interrupted`: повторите `/migrate` вручную. Ошибка одного поста не прерывает остальные; ошибка получения списка архива помечает весь обход как неполный (`failed`).

**Ограничение размера:** если полная история превышает бюджет в 60 000 символов тела Issue, пост читается, но не переносится и получает ошибку в отчёте. История не обрезается незаметно; автоматическое разбиение по комментариям пока не реализовано. Пустые/недоступные истории и неизвестные теги также отображаются в отчёте.

Если ответ создания Issue потерян по сети, следующая команда ищет маркер через список Issues. При удалении маркера и базы восстановление связи невозможно. Поиск в большом репозитории может быть медленным. Бот переносит сообщения с учётом доступа инициатора: видимость созданного Issue определяется целевым репозиторием.

`.env`, `routes.json` и `data/` исключены из Git. Токены в чат отправлять не нужно.

## Проверки

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q
.venv\Scripts\ruff check .
```

Тесты используют подменённые API, не создают реальные Issues и не подключаются к Discord. Полный запуск требует ваших Discord/GitHub токенов и реальных маршрутов.
